观察 LDR/STR 变体对寄存器与内存的影响

  • r2 = 0x00000078　r3 = 0x00005678　r4 = 0x12345678

Experimenting Load/Store (2)

给定内存，判断各指令的结果
任务：准备好代码，在 Debug 模式下用内存视图观察下列各行的行为。初始内存（小端）：
0x20008000=EE　01=8C　02=90　03=A7　04=A0　05=A0　06=A0　07=A0（即字 0xA7908CEE）。
代码行给定结果
LDRH r1, [r0]r0 = 0x20008000r1 = 0x00008CEE
LDRSB r1, [r0]r0 = 0x20008000r1 = 0xFFFFFFEE（= −18）
STR r1, [r0], #4r0=0x20008000, r1=0x07654321r0 存后 = 0x20008004
STR r1, [r0, #4]r0=0x20008000, r1=0x76543210r0 存后 = 0x20008000（不变）
STR r1, [r0, #4]!r0=0x20008000, r1=0x76543210r0 存后 = 0x20008004

答案（r0 依次）

  • [r0], #4（后索引）→ 使用时 r0 不变，存完 r0 = 0x20008004，写入 21 43 65 07。
  • [r0, #4]（偏移）→ r0 = 0x20008000 不变，写入 10 32 54 76（地址 0x20008004）。
  • [r0, #4]!（前索引）→ 先更新 r0 = 0x20008004，写入 10 32 54 76。

关键区别（务必背熟）

  • 偏移 [r0, #4]：地址 = r0+4，r0 不变。
  • 前索引 [r0, #4]!：先 r0 = r0+4，再访问 —— r0 被更新。
  • 后索引 [r0], #4：先按 r0 访问，之后 r0 = r0+4。
  • STR r1, [r0], #4 的 r1=0x7654321 只有 7 位 → 0x07654321。

Experimenting Addressing Modes (2)

多次 STR 后 r0 的最终值
任务：设定 r0 = 0x20000000、r1 = 0x12345678，逐步执行下列三行，记录内存并回答“代码结束后 r0 = ?”。
        STR     r1, [r0], #4    ; (1)
        STR     r1, [r0, #8]!   ; (2)
        STR     r1, [r0]        ; (3)
步骤有效地址r0 之后写入
(1) [r0], #40x200000000x200000040x20000000..03 = 78 56 34 12
(2) [r0, #8]!0x20000004+8 = 0x2000000C0x2000000C0x2000000C..0F = 78 56 34 12
(3) [r0]0x2000000C0x2000000C0x2000000C..0F = 78 56 34 12（重复）

答案

  • r0 最终 = 0x2000000C（= 0x20000000 + 4 + 8）。

Task 5

Arithmetic/Logic & APSR

逐条执行，记录 N Z C V
任务：每条指令单独执行，执行前都把寄存器初始化为 r0=0xFFFFFFFE、r1=0x00000001、r2=0xFFFFFFFD，记录结果的 N、Z、C、V。
代码行是否更新标志NZCV结果寄存器
ADD r3, r0, r1, LSL #4否（无 S）————r3 = 0x0000000E
SUBS r3, r0, r0是0110r3 = 0x00000000
ADDS r3, r0, r2是1010r3 = 0xFFFFFFFB
LSR r3, r0, #1否（无 S）————r3 = 0x7FFFFFFF
ASRS r3, r1, #1是（N/Z/C）011不变r3 = 0x00000000
ANDS r3, r0, r2是（N/Z）10不变不变r3 = 0xFFFFFFFC

推导

  • ADD（无 S）：r1<<4 = 0x10；0xFFFFFFFE + 0x10 = 0x10000000E，截断为 0x0000000E。指令不带 S → APSR 不变（这正是本题的第一个“坑”）。
  • SUBS r0, r0：结果 0 → Z=1；减法无借位 → C=1；同值相减不溢出 → V=0，N=0。
  • ADDS 0xFFFFFFFE + 0xFFFFFFFD：= 0x1FFFFFFFB → 截断 0xFFFFFFFB（MSB=1 → N=1）；无符号进位 → C=1；（−2）+（−3）=−5 仍在范围内 → V=0。
  • LSR（无 S）：逻辑右移，0xFFFFFFFE>>1 = 0x7FFFFFFF，标志不变。
  • ASRS r1,#1：0x00000001 算术右移 1 位 → 结果 0（Z=1），移出的最低位是 1 → C=1；V 不受移位影响。
  • ANDS：...1110 & ...1101 = ...1100 → 0xFFFFFFFC，MSB=1 → N=1，非 0 → Z=0；无移位 → C 不变，V 不变。

本题核心考点

  • 只有带 S 后缀的指令才写 APSR：ADDS / SUBS / ASRS / ANDS 会更新；ADD / LSR（无 S）不动标志。
  • 逻辑运算（ANDS/ORRS/EORS）带 S 时只更新 N、Z（有移位时才更新 C），不影响 V。
  • 移位指令（ASRS/LSLS/LSRS）更新 N、Z、C，不影响 V。
Task 6

Conditional Branches

条件分支与 xPSR

Code A（先判断后循环的变体）

__main  PROC
        MOV     r0, #0
        MOV     r1, #0
        B       check
loop    ADD     r1, r1, r0
        ADD     r0, r0, #1
check   CMP     r0, #10
        BLT     loop
endloop

Code B（while 型）

__main  PROC
        MOV     r0, #0
        MOV     r1, #0
loop    CMP     r0, #10
        BGE     endloop
        ADD     r1, r1, r0
        ADD     r0, r0, #1
        B       loop
endloop

两段代码都计算 r1 = 0+1+2+…+9，结果相同：r1 = 45。

代码触发/结束分支的 CMPNZCV说明
Code Ar0=9 时 CMP #10（BLT 成立，最后一次跳转）10009−10=−1，N≠V → BLT 成立
Code Ar0=10 时 CMP #10（BLT 不成立，跳出）0110相等，N=V → BLT 不成立
Code Br0=10 时 CMP #10（BGE 成立，跳出）0110相等，N=V → BGE 成立

答案

  • r1 = 45（两段代码结果一致）。
  • Code A：使循环继续的 BLT 在 r0=9 时成立，此时条件标志为 N=1 Z=0 C=0 V=0；使循环结束的 CMP 在 r0=10，标志 N=0 Z=1 C=1 V=0。
  • Code B：跳出的 BGE 在 r0=10，标志 N=0 Z=1 C=1 V=0。
  • 对应的 xPSR 条件位（高 4 位）：Code A 最后一次跳转 ≈ N=1（0x80000000 区）；结束/跳出时 C=1,Z=1（0x60000000 区）。（xPSR 其余位含 IPSR/T 位，随工程布局而变，验收时只需说明 N/Z/C/V 这 4 位。）
分支条件速记：BLT → N≠V；BGE → N=V；BEQ → Z=1；BNE → Z=0；BHI → C=1 且 Z=0。
Task 7

PUSH / POP

比较两种写法是否等价

Code 1

MOV     r1,#1
MOV     r2,#2
MOV     r3,#3
MOV     r4,#4
PUSH    {r1,r4,r3,r2}
POP     {r5-r7,r8}

Code 2

MOV     r1,#1
MOV     r2,#2
MOV     r3,#3
MOV     r4,#4
PUSH    {r1}
PUSH    {r2}
PUSH    {r3}
PUSH    {r4}
POP     {r5}
POP     {r6}
POP     {r7}
POP     {r8}
代码栈内容（低地址 → 高地址）r5r6r7r8
Code 11, 2, 3, 41234
Code 24, 3, 2, 14321

答案

  • Code 2 与 Code 1 行为“不相同”。Code 1 得到 r5..r8 = 1,2,3,4；Code 2 得到 r5..r8 = 4,3,2,1（被倒置）。
  • 原因：PUSH {r1,r4,r3,r2} 中，汇编器忽略书写顺序，一律按寄存器编号升序压栈，且编号小的在低地址（r1 在栈顶，最后弹出）；而 Code 2 逐个压栈，最后压入的 r4 在栈顶，第一个 POP 就把它弹给了 r5。
  • 修正方案（让 Code 2 与 Code 1 等价）：把压栈顺序反转——先压 r4、r3、r2、最后压 r1，弹出顺序不变：
    PUSH {r4} → PUSH {r3} → PUSH {r2} → PUSH {r1} → POP {r5} → POP {r6} → POP {r7} → POP {r8}，即得 r5=1、r6=2、r7=3、r8=4。
  • （等价做法：压栈顺序不变，改为逆序弹出 POP {r8}…POP {r5}。）
栈是“后进先出”：压栈顺序与出栈顺序相反，逐个 PUSH 时最后压的在栈顶。
Task 8

PC, SP, LR

观察 PC / SP / LR
任务：进入 Debug，确认 SP 指向 0x2000600；在 0x2000600 写 0x11111111、在 0x2000604 写 0x22222222，然后观察 PC、SP、LR。（若用现有工程，请把无关的数据段注释掉，或新建一个 *.s 文件。）
寄存器含义 / 观测到的值
SP栈指针 = 0x2000600（本任务设定；8 字节对齐，符合 AAPCS）
PC当前（下一条待执行）指令地址 → 在 Disassembly 窗口对照右端的地址列读取；B here 处 PC 即指向该行的地址
LR复位初值 = 0xFFFFFFFF；执行 BL myfunc 后 LR = 返回地址（here 的地址）

答案要点

  • PC 的具体数值取决于编译布局（即指令被链接到哪个地址），必须到 Keil 的 Disassembly/Registers 窗口单步读，无法凭空写死。
  • SP = 0x2000600（按本题设定）；它应指向栈顶且 8 字节对齐。
  • LR：复位后为 0xFFFFFFFF；BL 之后等于子程序返回地址（本文件里就是 here 那条指令的地址）。MOV pc, lr / BX lr 就是靠它返回。

演示时怎么说

  • SP：指出它指向 0x2000600，并说明栈是“向低地址增长”的。
  • PC：指出它始终指向将要执行的指令，单步时逐条前进。
  • LR：先看复位值 0xFFFFFFFF，再执行 BL，指出 LR 变成返回地址。
Task 9

Calling assembly function in C

C 调汇编：func1 / func2
任务：补全两个汇编函数：
func1：result1 = arg1 + func2(arg1, arg2)；
func2：result2 = arg1 - arg2。
; Task9_func.s  —— AAPCS: r0=arg1, r1=arg2, 返回 r0
        AREA    |.text|, CODE, READONLY
        EXPORT  func1
        EXPORT  func2
        ALIGN

func1   PROC
        PUSH    {r4, lr}        ; 保护 r4(被调用者保存) 与返回地址 lr
        MOV     r4, r0          ; r4 = arg1 (跨 BL 保留)
        BL      func2           ; r0/r1 仍是 arg1/arg2 → 调用 func2(arg1,arg2)
        ADD     r0, r4, r0      ; result1 = arg1 + func2(...)
        POP     {r4, pc}        ; 恢复 r4, 并返回 (pc<-栈顶 = 原 lr)
        ENDP

func2   PROC
        SUB     r0, r0, r1      ; arg1 - arg2
        BX      lr
        ENDP
        END

答案

  • func2：SUB r0, r0, r1；BX lr。
  • func1：先 PUSH {r4, lr}（保存 lr，因为要再 BL），MOV r4, r0 暂存 arg1，BL func2，再 ADD r0, r4, r0，最后 POP {r4, pc} 返回。
  • 运行结果：main 中 arg1=8、arg2=4 → func2 = 8−4 = 4 → func1 = 8+4 = 12（在 r0 / result 中）。

易错点

  • 调用别的函数前必须保存 lr（BL 会覆盖 lr），否则“回不来”。
  • 用到的 r4 属被调用者保存寄存器，必须 PUSH/POP。
  • 返回用 POP {r4, pc}（等价于恢复 r4 后 BX lr）。
  • func2 不调用其他函数、且只用 r0/r1（调用者保存），所以无需保存 lr/寄存器，直接 BX lr 即可。
Task 10

A more challenging AAPCS

补空 + 推导表达式
任务：分析混合 C/汇编代码，补全两个空以从栈上正确取得 B 和 G；推导代码实现的数学表达式；在 Debug 下追踪 process_sensor() 与 calibrate() 的寄存器与栈。
; Task10_func.s
calibrate PROC                      ; int calibrate(int s, int B, int G)
        PUSH    {r4, lr}
        SUB     r4, r0, r1          ; r4 = s - B
        MUL     r0, r4, r2          ; r0 = (s - B) * G
        POP     {r4, pc}
        ENDP

process_sensor PROC                 ; (w0,x0,w1,x1,B,G)
        PUSH    {r4, r5, r6, lr}
        MUL     r4, r0, r1          ; r4  = w0*x0
        MLA     r4, r2, r3, r4      ; r4  = w1*x1 + r4
        LDR     r1, [sp, #16]       ; 空1: r1 = B (第 5 个参数)
        LDR     r2, [sp, #20]       ; 空2: r2 = G (第 6 个参数)
        MOV     r0, r4              ; s = w0*x0 + w1*x1
        BL      calibrate
        POP     {r4, r5, r6, pc}
        ENDP

栈追踪（进入 process_sensor 到取参数）

时刻[sp+0][sp+4][sp+16][sp+20]
刚进入 process_sensor（push 前）BG——
执行 PUSH {r4,r5,r6,lr} 后（SP −16）r4r5BG

答案

  • 两个空：LDR r1, [sp, #16]（B，第 5 个参数）与 LDR r2, [sp, #20]（G，第 6 个参数）。
  • 数学表达式： output = ((w0·x0 + w1·x1) − B) · G。
  • 数值：s = 10×2 + 20×3 = 20 + 60 = 80；(80 − 10) × 2 = 140 → output = 140。

寄存器/栈追踪（数值验证）

步骤关键寄存器 / 栈值
main 调用r0,r1,r2,r3 / [sp],[sp+4]10, 2, 20, 3 / B=10, G=2
PUSH {r4,r5,r6,lr}SPSP − 16
MUL r4,r0,r1r410×2 = 20
MLA r4,r2,r3,r4r420×3 + 20 = 80（即 s）
LDR r1,[sp,#16] / LDR r2,[sp,#20]r1, r2B=10, G=2
BL calibrater0, r1, r2s=80, B=10, G=2
SUB r4,r0,r1r480 − 10 = 70
MUL r0,r4,r2r070 × 2 = 140

AAPCS 关键规则（本题考点）

  • 前 4 个参数依次放 r0–r3；第 5 个及以后压栈，进入函数时第 5 个参数在 [sp]、第 6 个在 [sp+4]。
  • 函数内一旦 PUSH，SP 变化，栈参数偏移要加上被压入的字节数（本题 PUSH {r4,r5,r6,lr} = 4 个寄存器 = 16 字节，故 [sp+16]/[sp+20]）。
  • MUL Rd,Rm,Rs → Rd=Rm×Rs；MLA Rd,Rm,Rs,Rn → Rd=Rm×Rs+Rn。

附录 B · Keil 上机与验收提示

  • 工程搭建：Keil 新建 ARM 工程（器件选你课程用的 STM32F401/ARMCM4）。纯汇编任务直接把对应 TaskN.s 加入工程；Task 8–10 说明见各题。
  • 入口符号：示例用课件里的 __main PROC。若你的启动文件要求别的入口名（如 main / Reset_Handler），把标号改成与启动文件一致即可。
  • 0 error / 0 warning：汇编文件结尾务必有 END；用 C 的题目避免“函数未 return”告警（本解用 while(1) 收尾）。
  • printf 说明（Task 10）：课件用了 printf。若无串口/ITM 重定向，链接可能报半主机相关告警；此时改为在调试器观察 r0 / g_output 即可满足验收（本解已按此写好）。如需真实输出，需补一个 fputc 重定向。
  • 演示口径：每个任务都按“编译 → 单步 → 指出结果怎么算出来”三步演示；建议每人认领 2 个任务（如 1+5、3+4、7+9、8+10 等，注意覆盖 load/store、寻址、标志、栈、混合编程五类知识点）。
